# Reports and Exports

## Goal
Make collection information useful outside the app while keeping exports intentional and privacy-aware.

## Report types
The future catalog should support useful reports such as:
- Full collection inventory
- Coins by country or denomination
- Paper money by issuer, series, or denomination
- Certified items
- Items needing research or verification
- Items missing photographs
- Items with Unknown / Not Checked fields
- Acquisition and disposition summaries
- Valuation summaries

## Export formats
Where practical, support portable formats such as CSV for structured data and a human-readable report format for sharing or printing. A complete backup/export is separate from a presentation report.

## Privacy controls
Before creating a shareable report, the owner should be able to exclude private fields such as purchase price, value, storage location, private notes, provenance details, and personal information.

## Media
A report may include selected owner photographs when the owner chooses to include them. Reference images should remain clearly identified as reference material.

## Accuracy
Reports should be generated from the current master records and should indicate when values are estimates or when information remains unverified.

## No destructive export
Generating a report or export must never modify or delete the underlying collection records.

## Future-proofing
Export formats should be documented and versioned so collection data remains portable if the application changes later.
