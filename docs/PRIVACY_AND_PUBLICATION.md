# Privacy and Publication Rules

## Master collection
The master collection should be designed so private collection data can remain private even when the application is hosted publicly.

## Public website vs private data
Publishing the application code or a public catalog shell does not require publishing the user's collection records, personal notes, storage locations, purchase prices, or photographs.

## Default principle
Private collection information should be private by default. Any future sharing feature should require an intentional user action and clearly explain what is being shared.

## Sensitive fields
Treat these as private unless the owner explicitly chooses to share them:
- personal information
- purchase price
- estimated value
- storage location
- provenance details that reveal private information
- owner photographs where appropriate
- private notes

## Reference material
External reference images and research sources remain separate from owner photographs and collection records. A reference image must never be presented as proof that the pictured item is the owner's item.

## Future-proofing
Access controls and publication settings should be implemented at the data layer, not only by hiding buttons in the interface.
