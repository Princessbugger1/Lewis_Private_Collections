# Search and Filter Plan

The master catalog should make the collection easy to find without requiring users to remember exactly where an item was entered.

## Global search
Search should be able to find records by:
- catalog/record number
- category
- country/issuer
- description/type
- denomination
- date/year
- mint mark
- series
- serial number
- certification number
- variety/error
- grade
- storage location
- collection/set
- notes

## Coin filters
Examples:
- mint mark (P, D, S, C, CC, O, W, etc.)
- date range
- denomination
- grading service/grade
- silver/gold/other composition
- variety/error
- three-state checks

## Paper Money filters
Examples:
- denomination
- date
- series
- serial number
- Federal Reserve district
- star note
- signature combination
- printing information
- errors/varieties
- grade/condition

## Three-state filters
Applicable fields must distinguish:
- Unknown / Not Checked
- Yes
- No

## Privacy
Search indexes should not expose collection records outside the access permissions of the catalog. Future cloud/public-sharing features must not accidentally turn private collection metadata into public search results.

## Future-proofing
Filters should operate on structured master-record fields rather than parsing display text. This allows future simple versions to reuse the same search engine.
