# Accessibility and Touch Interaction

## Goal
Make the catalog comfortable and reliable on a phone without sacrificing the uncluttered design.

## Touch targets
Interactive controls should have enough touch area to use accurately on a phone. Tiny visual elements such as reference thumbnails may remain visually small, but the tappable area around them should be practical.

## Three-state controls
Three-state fields should provide clear state feedback:
- ❓ Unknown / Not Checked
- ✅ Yes
- ❌ No

Tapping cycles through the three states. The state must also be understandable without relying only on color.

## Photo interaction
Tapping an owner-photo thumbnail opens the full photograph. Tapping a reference thumbnail opens the reference image and source information when available.

## Text and labels
Important actions and fields should have readable labels. Icons may supplement text but should not be the sole explanation for an important action.

## Keyboard and other input
Forms should remain usable with a physical keyboard or assistive input where supported by the device/browser.

## Error prevention
Destructive actions should be clearly distinguished and should not be triggered by an accidental tap. Restore/import operations should provide validation before changing existing records.

## Future-proofing
Accessibility behavior should be shared by advanced and basic catalog views so a simplified version does not lose essential usability safeguards.
