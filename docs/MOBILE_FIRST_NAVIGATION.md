# Mobile-First Navigation

## Goal
Make the catalog fast to use on a phone while keeping advanced capabilities available without overwhelming the main screen.

## Primary navigation
The main experience should prioritize:
- Collection list
- Search
- Add item
- Filters
- Reports or tools

Less frequently used administration and advanced settings should live in secondary areas.

## Record screen
A collectible detail screen should present the most important identification and owner-photo information first, with advanced research, provenance, valuation, history, and technical information available in organized sections.

## Compact controls
Controls that are used frequently should be reachable without excessive scrolling. Small visual elements can remain visually unobtrusive when their tap target is larger than the visible element.

## Back navigation
Navigation must preserve unsaved changes safely and should warn before abandoning meaningful edits.

## Offline-friendly design
Where the application architecture permits, the interface should remain usable when connectivity is temporarily unavailable, with clear indication of operations that require an online service.

## Performance
Large collections and photographs should load progressively so the initial catalog screen does not attempt to load every full-size image at once.

## Future-proofing
Navigation should be based on functions and stable record identifiers rather than hard-coded positions, allowing new categories and tools to be added without redesigning the entire app.
