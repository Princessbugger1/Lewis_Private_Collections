# Phone / Desktop UX Rules

The catalog must work well on both phones and larger screens without hiding important controls.

- Use responsive layouts rather than a separate, permanently hidden mobile experience.
- Settings must remain easy to find on both layouts; do not bury the desktop/mobile switch.
- Controls such as Accept, Change, Reject, and three-state status buttons should be medium-sized: clearly visible and comfortably tappable, but not oversized cards.
- On narrow screens, controls may wrap or compact while preserving readable labels/icons and touch targets.
- Tables and dense collection views should have an intentional mobile presentation rather than forcing a desktop table into an unreadable width.
- Switching display modes must not change, duplicate, or delete collection records.
- The user's selected display mode is a preference and should be preserved by backup/restore where appropriate.
- Phone and desktop layouts must expose the same underlying catalog capabilities; responsive presentation may differ, but features must not silently disappear.
