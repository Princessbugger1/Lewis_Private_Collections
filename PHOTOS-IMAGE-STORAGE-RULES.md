# Photos and Image Storage Rules

Photos are valuable catalog evidence and must be handled as collection data, not as disposable interface files.

- Each photo/attachment should have a stable association with its parent record.
- Multiple photos per item must be supported so users can capture obverse, reverse, edge, slab, label, packaging, and supporting documentation when applicable.
- Original images should not be silently replaced by edited/cropped versions; preserve the original when the workflow supports editing.
- Image thumbnails/previews may be generated for performance, but they must remain linked to the original.
- Photo order and role (for example obverse, reverse, slab label) should be editable.
- A photo imported for research must not automatically become the permanent primary image without user confirmation when ambiguity exists.
- Photos remain subject to the same privacy and sharing permissions as the parent record.
- External research must not automatically upload every stored collection photo.
- If a user explicitly sends a selected image for research, only that selected image should be transmitted unless the feature clearly requires more.
- Removing a photo should require deliberate action and should not delete the parent coin record.
- Backup/export rules should preserve photos where the chosen format supports them.
- Image metadata should be minimized when practical so unnecessary device/location metadata is not exposed during sharing or research.
