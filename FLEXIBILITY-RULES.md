# Catalog Flexibility Rules

The catalog is intended to evolve without locking the user into today's fields or research provider.

- Existing records remain editable.
- Normal text fields can be corrected, replaced, or cleared and then saved.
- Three-state fields preserve Unknown / Yes / No as distinct values.
- Research categories can be expanded later, including coins, tokens, medals, and counterfeit/suspected-counterfeit pieces.
- Research provider code stays behind an adapter so the provider can be replaced or removed later.
- Research suggestions are separate from saved catalog values until the user explicitly accepts them.
- Original photos and user notes should not be destroyed merely because a research result is rejected or corrected.
- Features should be isolated where practical so they can be removed or revised without rewriting the core catalog.
